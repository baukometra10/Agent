# Destination vision (north star)

Evolve should feel like a world-class AI software organization:

1. Understand any codebase in any language stack.
2. Hold a living, sourced memory of the system.
3. Propose evolution with clear *why*, impact, and risk.
4. Accept human chat/requests and turn them into plans + code.
5. Execute only after confirmation; never mix projects.
6. Continuously re-evaluate and improve — with email/control-plane approvals.

## Independence doctrine

The agent must be **highly independent by default**:

| Capability | Autonomy |
|------------|----------|
| Understand / analyze / plan | **Automatic** per project |
| Draft proposals with rationale | **Automatic** |
| Interactive chat (Cursor-like) | **On-demand** with tools + memory |
| Execute code changes | **Human-gated** |
| Merge / deploy | **Human-gated** |

## Cursor-class — but stronger

Evolve aims to match Cursor’s interactive coding loop (chat → tools → edits), then exceed it with:

- Whole-system Project Intelligence & Knowledge Graph
- Multi-agent critique before acceptance
- Continuous autonomous roadmaps per project
- Proposal/approval discipline (why / impact / risk) before apply
- Hard multi-project isolation and evolution cycles

Independence means: the system keeps thinking, discovering, and planning without micromanagement. It does **not** mean unsupervised production changes.

Each project runs in hard isolation. No shared memory, workspace, or roadmap across projects.

**Company doctrine:** Spixa owns a family of specialized minds — it is not merely a shell over third-party models.

**Model ownership doctrine:** Spixa Proprietary Intelligence Ecosystem — External Teacher → Owned Specialty Family (Reasoner · Coder · Architect · Critic · Vision · Embed) under the Intelligence Orchestrator. See `docs/SPIXA_INTELLIGENCE.md` and `docs/MODEL_OWNERSHIP.md`. Local-first routing; teachers escalate; verified outputs distill into owned adapters. Target: ~85% successful tasks on internal models after maturity — measured, not promised by date.

**Next chapter (after platform foundation):** real training · independent tests · owned weights/data · proof on real engineering tasks.

**Non-goal:** Training a huge foundation model from scratch is not a success gate. Shared open-weight base + owned adapters first; full base independence is optional later.

Intelligence roadmap **I1–I6** builds on platform phases 1–51; GPU/real-train proof waits for private staging deploy.
